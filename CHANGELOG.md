# Changelog

## 0.4.0 (unreleased)

### Added
- Holdouts, evaluated like the JS SDK. Context data may carry `holdouts` (each with `id`, `name`, `iteration`, `seedHi`, `seedLo` and `split`), and an experiment lists the holdouts covering it in `holdoutIds`. Each covering holdout places the unit in an arm, drawn from the holdout's `split` and seeds with the covered experiment's unit, and kept for the context while the holdout's `iteration` is unchanged. Arm 0 holds the unit out of the experiment; in a holdout with three arms, arm 1 holds the unit out only of experiments that are not full-on. A unit held out by any of its holdouts gets the control variant (`assigned` false), and audience, full-on, traffic and custom assignments do not apply. A variable read returns the held-out experiment's control value only when no assigned or overridden experiment defining the same key wins it. The held-out experiment publishes no exposure of its own, unless an override or a matching assignment rule chose its variant: both still win over the holdout. The first treatment or variable read of a covered experiment queues each holdout's exposure, named after the holdout, with the arm as its variant. That happens once per holdout, unit type and holdout iteration, however many reads or covered experiments follow; a new iteration is a new exposure. While the covered experiment's unit is not set, a holdout neither holds the unit out nor publishes. `peek_treatment` and `peek_variable_value` publish nothing. Payloads without holdouts are assigned and published exactly as before.
- `ContextData.holdouts`, `Experiment.holdoutIds` and `Experiment.holdoutType` (all default `None`) and `sdk.json.holdout.Holdout`. Holdout entries may be the dicts the default deserializer produces, any `Mapping`, or objects with the same attributes; entries without a non-empty `split`, malformed entries (for example ids, seeds or split values that are not JSON numbers) and unknown fields are ignored.

### Fixed
- Shared variable keys: only the winning experiment is exposed. When two or more running experiments define the same variable key, `get_variable_value` queued an exposure for every experiment it checked on the way to the value, including ones the unit was not in (a strict audience mismatch, or a unit type that is not set), so those users were recorded in experiments they never saw. And when the first experiment the unit was in had given it a variant without the key, the read fell through to the next experiment, so which experiment supplied the value (and was exposed) depended on the arm the unit got, biasing both experiments. Anyone with two or more running experiments sharing a variable key is affected; their exposure counts for the losing experiments drop after upgrading. So is anyone reading a key that only one experiment defines when the unit is not in it: a strict audience mismatch or a unit type that is not set used to be exposed by `get_variable_value` (a strict mismatch with `audienceMismatch` true) and now nothing wins the key, so no experiment exposure is published. A visited candidate can still publish its holdouts’ exposures when its unit is set. `get_treatment` still exposes such an experiment. The rule now applied, as in the Java SDK: the candidates are the experiments defining the key in any variant, in id order; the first one the unit is assigned to, overridden in or rule-assigned to wins; if the winner's variant lacks the key the default is returned; only the winner is exposed. When no candidate wins, the first held-out candidate supplies its control value, else the default is returned with no exposure. `peek_variable_value` resolves the same winner and exposes nothing. Holdout exposures are unchanged in kind: each candidate checked still publishes its holdouts' exposures, now before the winner's own exposure. An overridden or rule-assigned held-out experiment now wins the key like any other override or rule, so its variant lacking the key returns the default instead of a later experiment's value.

### Changed
- Exposure counts change for experiments read with `get_variable_value`: an experiment the unit is not in (a strict audience mismatch, or a unit type that is not set) is no longer exposed by a variable read, even when it is the only experiment defining the key, and an experiment that is checked for a shared key but does not win it is no longer exposed, and a winner whose variant lacks the key returns the default instead of a later experiment's value. See Fixed. This includes an override to a variant number the experiment does not have: the overridden experiment wins the key and is exposed, and the default is returned (0.3.0 skipped it and used the next experiment).
- A variable read stays consistent across the context lifecycle: when `set_unit` adds a unit while the read is checking the key's experiments, the read checks the key again before exposing anything; an experiment a concurrent `refresh` removed never wins the key; and the built-in queue accepts the winner together with its holdouts, so a concurrent close publishes both or neither.
- A `queue_exposure` override that raises while being offered a holdout exposure no longer stops the remaining holdout exposures of that read (from `get_treatment` or `get_variable_value`): every one is offered and the first error is raised afterwards, as in the Java SDK.
- Payloads with `holdouts` change assignment for held-out units. 0.3.0 ignored holdouts, so a unit the backend holds out still got its experiment's variant and an experiment exposure. From 0.4.0 that unit gets the control variant, and the holdout's exposure replaces the experiment's. Units that are not held out keep their variants, but their reads of covered experiments now also publish the holdout exposures. Payloads without holdouts are unaffected.
- The `X-Agent` header and `sdk_version` report `0.4.0`.

## 0.3.0

### BREAKING
- `ContextEventHandler` renamed to `ContextPublisher` (`context_event_handler` deprecated). The v0.2.4 import paths (`sdk.absmartly.ABSmartlyConfig`, `sdk.absmartly.DefaultContextEventHandler`, `ContextEventHandler` from `sdk.context_event_handler`, `sdk.absmartly_config` and `sdk.context`) still work and do not warn on import; `ContextEventHandler` stays a plain base class (a subclass without `publish` can still be instantiated) registered as a virtual `ContextPublisher`.
- `get_custom_field_type` renamed.
- `get_variable_keys()` keeps the v0.2.4 shape (one experiment name string per key), but when several experiments define a key it now returns the lowest-id experiment instead of v0.2.4's last-in-payload one.
- `get_variable_value`/`peek_variable_value` with a key shared by several experiments now take the value from the lowest-id experiment the unit is assigned to or overridden in (visiting experiments in id order), instead of v0.2.4's last-in-payload experiment; each visited experiment is exposed.
- Audiences are re-evaluated after `set_attribute`: a unit whose attributes change can move in or out of an experiment's audience (so between assigned and the control/default value), which emits the extra exposure for the re-evaluated experiment. v0.2.4 evaluated the audience only once.
- **BREAKING:** read methods now raise "ABSmartly Context is not yet ready" before the context is ready, and the closed error after close, instead of returning defaults. A context whose load failed is ready and returns control/default values.
- JSON expr `in` operator is haystack-first (CONTAINS semantics); `eq(null, null)` returns null.
- `set_unit` keeps numeric UIDs as numbers (hashed like the JS SDK, e.g. `125.75` hashes as `"126"`) and rejects values that are neither a string nor a number with "Unit '<type>' must be a string or a number.".
- `track` raises "Goal '<name>' properties must be of type object." when properties cannot be converted with `dict()`; any `Mapping` or list of pairs is still accepted, as in v0.2.4.

### Changed
- Audiences and assignment-rule conditions are now always evaluated with `application` and `environment` set to the application and environment names configured in the SDK. They are layered under any user-set attributes (system values first, then your attributes overlay them), so a value you set with the same name — at any time, including after the context is created — always wins. Names that are not configured or empty are left out of the evaluation map. These system attributes are evaluation-only: they are never added to published attributes (the collector adds them server-side), not even with `include_system_attributes=True`, which only adds `sdk_name` and `sdk_version`; `get_attributes()` does not return them. The SDK never adds `app_version` for audiences (an `app_version` you set yourself is still evaluated and published like any other attribute).

  **This changes assignment for running experiments.** A unit in an experiment with Audience enforced (`audienceStrict`) and an `environment` or `application` condition currently gets variant 0, even when it matches the condition and even when the experiment is full-on. After upgrading, a matching unit is randomised normally (or gets the full-on variant). Those experiments are broken today; this release fixes them, but their exposures will change.
- The `X-Agent` header is now versioned, `absmartly-python-sdk/<version>` (for example `absmartly-python-sdk/0.3.0`), derived from the package version. The collector stores it in the export `agent` column, so filters on `absmartly-python-sdk` must match the prefix instead.
- Every published exposure now carries `ruleOverride` (`true` when an assignment rule chose the variant, otherwise `false`), as the JS SDK sends it. Consumers comparing raw publish payloads see the new field.
- `X-Application-Version` carries the configured `application_version` (the new `ABsmartly.create(..., application_version=...)` argument or the `application_version` client-config environment variable) only when it is 1-18 ASCII digits after trimming; anything else, such as `"2.4.1"`, is sent as `"0"`, as before, because the collector reads the header as a number. `Client.get_application_version()` returns the configured value unchanged.

### Added
- Assignment rules (`assignmentRules` in the context data), evaluated like the JS SDK: the first matching `assign` or `split` rule (scoped by the configured environment) decides the variant before the audience and is exposed with `ruleOverride: true`. Split percentages are read like JS `parseFloat` (`"20abc/80"` is 20/80); malformed or unknown rules are skipped without affecting other experiments.
- `semver_eq`, `semver_gt`, `semver_gte`, `semver_lt` and `semver_lte` audience operators; numbers are converted like the JS SDK (`1e-7` compares as `"0.0000001"`).
- `ContextConfig.include_system_attributes` (default `False`) adds `sdk_name` and `sdk_version` to published attributes.
- `Context.get_variable_keys_all()` returns every experiment defining each variable key, in experiment id order (matching the JS SDK's `variableKeys()`); `get_variable_keys()` keeps the v0.2.4 shape (one experiment name per key, the lowest id).
- `ContextError(RuntimeError)` / `ContextValueError(ValueError)`: lifecycle and unit errors keep their v0.2.4 messages (`'ABSmartly Context is closed'`, `'ABSmartly Context is closing'`, `'ABSmartly Context is not yet ready'`, `'Unit already set.'`, `'Unit UID must not be blank.'`) and expose the cross-SDK wording as `canonical_message`.
- `sdk.utils`: `hash_unit`, `utf8_bytes`, `base64_url_no_padding`, `is_object`, `is_numeric`, `is_promise`.
- Finalize aliases, `get_unit`, `get_units`, `get_attribute`, `get_attributes`, `ready_error`; `EventType` export.
- `custom_assignments` (deprecated alias for the `cassigmnents` typo).
- `Context.cassignments` kept as a deprecated property (with setter) proxying `Context.custom_assignments`.

### Fixed
- `DefaultVariableParser.parse` and `DefaultContextDataDeserializer.deserialize` return `None` on invalid input again, as in v0.2.4. Context logs an ERROR for an unparseable variant config, or one that is not a JSON object (no variables are indexed for it), and treats `None` context data as a failed load (or a failed refresh) instead of hanging.
- `DefaultHTTPClient` accepts v0.2.4-style configs without `retry_status_forcelist` / `retry_allowed_methods` and uses the v0.2.4 policy for them.
- Audience regex matching no longer runs in a thread pool or caps pattern length (the timeout could not interrupt a match); invalid patterns still evaluate to `None`.
- `DefaultHTTPClient` keeps the v0.2.4 retry policy (GET/POST on 502/503, publish PUT not retried) and its exhausted-retry behaviour (a `requests.exceptions.RetryError` once GET retries are exhausted); the wider policy is opt-in via `DefaultHTTPClientConfig.retry_status_forcelist` / `retry_allowed_methods`.
- A cached assignment records the attribute sequence after an unchanged audience re-check, so it is not re-evaluated on every read.
- `refresh()` works before the context is ready and on a context whose first fetch failed, as in v0.2.4; a successful refresh clears the failed state so new exposures and queued goals are published (control exposures queued while failed are dropped). If the initial fetch completes after a pre-ready refresh, it does not replace the refreshed data or log `READY`.
- The default publisher built by `ABsmartly` is a `DefaultContextEventHandler` again, so v0.2.4 `isinstance` checks against `DefaultContextEventHandler` and `ContextEventHandler` still hold.
- `close()` logs `EventType.CLOSE` again (as in v0.2.4), followed by the new `EventType.FINALIZE`.
- A failed final publish no longer restarts the refresh timer; the events stay queued so `close()` can be retried.
- The `ready`, `error`, `refresh` and `finalize` events are logged before the matching future settles, so callers woken by it already see the event.
- Custom field values parsed lazily; refresh timer race; daemon timer threads; owner-safe ReadWriteLock; `DefaultHTTPClient.post` uses POST.
